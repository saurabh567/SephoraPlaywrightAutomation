# AI Automation Layer

This folder turns the existing Playwright + Cucumber + Page Object framework into an AI-assisted automation platform.

## Folder Structure

```text
ai/
  agents/      Specialized automation agents
  config/      AI provider and framework path configuration
  docs/        Architecture diagrams and implementation notes
  mcp/         MCP server usage design
  memory/      Shared agent memory
  output/      Generated AI artifacts
  prompts/     Prompt templates
  tools/       Local tools used by agents
  workflows/   Multi-agent workflow orchestration
```

## Environment

```env
OPENAI_API_KEY=your-api-key
OPENAI_MODEL=gpt-4.1-mini
OPENAI_BASE_URL=https://api.openai.com/v1
AI_TEMPERATURE=0.2
AI_MAX_TOKENS=4000
```

`OPENAI_API_KEY` is required. AI execution fails explicitly when the LLM or embedding
provider is not configured.

## Agent Usage

```bash
npm run ai:agent -- --agent testCaseGeneration --requirement "Validate Amazon India search for valid and invalid products"
```

```text
utils/runCucumberWithAi.js

  -> ai/workflows/runPostExecutionAgents.js

  -> LocatorHealingAgent RAG
```


## Phase 5 — Locator Healing Engine

Automated recovery of broken Playwright/Cucumber locators when the DOM changes.

### Components

```text
ai/agents/locator-healing/
  LocatorHealingEngine.ts       Orchestrates the full healing workflow
  LocatorConfidenceScorer.ts    Scores candidate replacements 0.0–1.0
  LocatorHistoryStore.ts        Persistent locator version/success/failure history
ai/agents/locatorHealingApplier.ts   Safe patch/apply/backup of locator files
ai/agents/locatorHealingAgent.ts     RAG-backed recommendation agent (LLM)
utils/runLocatorHealing.ts           CLI entry point
```

### How it works

1. When a locator fails, capture `{ locator, page, feature, scenario, error, locatorName }`.
2. `LocatorHealingEngine._generateCandidates()` proposes alternatives:
   - XPath ↔ CSS conversion (`@id`, `@class`, `text()` extraction)
   - class → attribute (`[class*="..."]`), `data-testid` adaptation
   - index-position removal, and rollback to historical versions
3. `LocatorConfidenceScorer` scores each candidate using weighted factors:
   `domSimilarity (0.30) + historicalSuccess (0.25) + locatorTypeStability (0.20) +
   attributeRichness (0.15) + proximityMatch (0.10)`.
4. If confidence ≥ threshold (default `0.80`) and mode is `apply`, the replacement
   is applied through `LocatorHealingApplier` (which only does safe backup/patch logic).
5. Every failure/replacement is recorded in `LocatorHistoryStore` JSON history under
   `ai/memory/locator-history/`.
6. A markdown report is generated at `reports/ai/locator-healing-report.md`.

### Usage

```bash
# Recommend replacements (no file changes)
npm run heal:locators

# Dry-run auto-apply decisions
npm run heal:locators:dry

# Auto-apply replacements with confidence >= threshold
npm run heal:locators:apply

# Custom mode/threshold
node -r ts-node/register utils/runLocatorHealing.ts --mode apply --threshold 0.85

# Extract failures from a cucumber report dir first
node -r ts-node/register utils/runLocatorHealing.ts --reportDir reports/web
```

Failures are read from `ai/input/failed-locators.json` (generated by
`node utils/generateFailedLocators.ts --reportDir <dir>`). Results are written to
`reports/ai/locator-healing-results.json`.

### Outputs

```text
reports/ai/locator-healing-report.md      Human-readable healing report
reports/ai/locator-healing-results.json   Structured healing results + analytics
ai/memory/locator-history/locator-history.json   Persistent locator history
ai/memory/locator-history/                Per-locator JSON history files (future split)
```
