# Framework Guide

This document explains the purpose of each folder and important file in the Sephora Playwright Cucumber framework.

## Root Files

- `README.md`: Project overview, setup commands, execution commands, reporting details, and interview explanation.
- `FRAMEWORK_GUIDE.md`: File-by-file framework explanation for learning and interview preparation.
- `package.json`: Node.js project metadata, npm scripts, and dependency list. JSON does not support comments.
- `package-lock.json`: Locked dependency versions generated by npm. Do not edit manually.
- `cucumber.js`: Cucumber runtime configuration. It loads hooks, step definitions, feature paths, reports, retries, parallel execution, and timeout.
- `playwright.config.js`: Playwright-level configuration for browser defaults, screenshots, traces, videos, viewport, and report output.
- `Jenkinsfile`: Jenkins declarative pipeline for checkout, dependency installation, browser installation, test execution, report generation, and artifact archiving.
- `ai/`: AI-assisted automation layer containing agents, prompts, workflows, tools, memory, MCP design, and architecture documentation.
- `.gitignore`: Excludes generated files such as `node_modules`, reports, screenshots, videos, logs, and environment files from Git.
- `.env`: Local environment values such as `BASE_URL`, `BROWSER`, `HEADLESS`, and `TIMEOUT`. This file is intentionally ignored by Git.

## `features/`

Contains Cucumber Gherkin feature files. These files describe test scenarios in business-readable `Given`, `When`, `Then` format.

- `home.feature`: Home page scenarios such as logo, search box, header links, navigation menus, banners, and search.
- `makeup_face.feature`: Makeup Face listing page scenarios such as banner, category tabs, filters, products, sort option, and breadcrumbs.
- `product_details.feature`: Product details page scenarios such as title, brand, price, rating, shade, delivery, quantity, and Add To Bag.
- `cart.feature`: Shopping bag page scenarios such as cart title, item details, quantity controls, price summary, checkout, coupon, and pincode.

## `step-definitions/`

Contains JavaScript glue code that maps Gherkin steps to automation code. In this simplified framework, step definitions directly create the required page object using `new PageClass(this.page)`.

- `common.steps.js`: Shared steps used across multiple feature files, such as opening pages, checking page title, searching products, and generic text validation.
- `home.steps.js`: Home page-specific validation steps that call `HomePage` locators and methods.
- `makeupFace.steps.js`: Makeup Face listing page-specific validation and action steps.
- `product.steps.js`: Product details page-specific validation steps.
- `cart.steps.js`: Shopping bag page-specific validation and action steps.

## `pages/`

Contains Page Object Model classes. Page classes store locators and page-specific actions.

- `BasePage.js`: Common reusable wrapper methods such as `open`, `click`, `fill`, `verifyVisible`, and `verifyTextVisible`.
- `HomePage.js`: Home page locators and actions such as opening home page, searching product, and opening bag.
- `MakeupFacePage.js`: Makeup Face listing page locators and actions.
- `ProductDetailsPage.js`: Product details page locators and actions such as delivery check and Add To Bag.
- `CartPage.js`: Shopping bag page locators and actions.
- `LoginPage.js`: Login-related locators and actions.

## `hooks/`

Contains global Cucumber hooks for test lifecycle management.

- `hooks.js`: Launches the browser before execution, creates a fresh context and page before every scenario, starts tracing, captures screenshots on failure, closes context after each scenario, and closes browser after all scenarios. During parallel execution, each Cucumber worker gets its own browser instance and worker-specific artifact names.

## `config/`

Contains framework environment configuration.

- `env.config.js`: Reads `.env` values and exposes active environment, base URL, browser, headless mode, timeout, retries, parallel count, viewport, trace, and video settings.

## `utils/`

Contains helper utilities used by the framework.

- `configReader.js`: Provides simple methods to read configuration values from `env.config.js`.
- `logger.js`: Creates framework logging for execution messages.
- `cleanReports.js`: Cleans old reports, screenshots, videos, traces, and logs before a new test run.
- `generateReport.js`: Generates the final Cucumber HTML report from JSON report output.
- `runCucumberWithAi.js`: Runs Cucumber and then triggers post-execution AI analysis while preserving the original Cucumber exit code.

## `test-data/`

Contains external test data in JSON format. JSON does not support comments, so test data files are documented here.

- `products.json`: Product-related test data such as search term and pincode.
- `users.json`: User-related test data such as login credentials or test users.

## Generated Runtime Folders

These folders are created during execution and are normally ignored by Git.

- `reports/`: Cucumber JSON/HTML reports, screenshots, videos, and traces.
- `logs/`: Execution logs.
- `screenshots/`: Optional screenshot output folder.
- `videos/`: Optional video output folder.
- `node_modules/`: Installed npm dependencies.
- `ai/output/`: Generated AI artifacts such as feature drafts, code drafts, summaries, and patch plans.

## Execution Flow

```text
Feature file
  -> Step definition
  -> Page object class
  -> BasePage reusable method
  -> Playwright browser action
```

## Parallel Execution

Cucumber parallel execution is controlled through the `PARALLEL` environment variable.

```bash
npm run test:parallel
npm run test:parallel:2
PARALLEL=3 npm test
```

In Jenkins, the `Jenkinsfile` sets:

```text
PARALLEL=2
```

Each worker launches its own browser in `hooks.js`. Screenshots and traces include the worker id in the filename, and videos are stored under `reports/videos/worker-<id>/`.

## Cross-Browser Execution

Cross-browser execution is handled by `utils/runCrossBrowser.js`. The runner executes the same Cucumber suite separately for each browser and stores each browser's artifacts in its own report folder.

```bash
npm run test:cross-browser
BROWSERS=chromium,firefox npm run test:cross-browser
TAGS=@smoke npm run test:cross-browser
```

Default browsers:

```text
chromium
firefox
webkit
```

Report locations:

```text
reports/cross-browser/chromium/
reports/cross-browser/firefox/
reports/cross-browser/webkit/
```
